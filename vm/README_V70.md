# Puppy50 Web v70 — Normal browser preview

Puppy50 Web v70 is a **QEMU-only experimental Linux browser**. It loads the compressed operating system into RAM, boots without a writable hard disk, and can remove its optical boot medium after startup.

## Improvement over v69

- Normal user-controlled Firefox browser homepage. No automatic Example Domain tab opens after a timer.
- Direct links to Example Domain, Wikipedia, Mozilla, Google, and Firefox preferences. The address bar remains unrestricted for authorized public websites.
- A local **Network status** page generated by the guest's actual DHCP/DNS/certificate-verified HTTPS startup probe, showing offline/direct/host-bridge mode and meaningful failure information.
- The proven non-root Firefox, real CA certificate bundle, Xorg, mouse/keyboard input, x86_64 kernel, initrd, user-mode QEMU e1000 NAT driver and TLS-preserving bridge remain unchanged except for the user-facing startup script and status wrapper.
- Optional read-only host DNS/public HTTPS diagnostic before boot. It never changes host networks, reads passwords, or prints proxy credentials.

## Run with your existing Wi-Fi, Ethernet, or hotspot

1. Connect **the host Xubuntu computer** to Wi-Fi, wired Ethernet or a phone hotspot.
2. Install QEMU and Python: `sudo apt install qemu-system-x86 python3`.
3. Extract the complete v70 bundle in one directory.
4. Run `bash launch_linux_v70.sh`.
5. Once Firefox appears, choose a site on the home page or enter any URL using **Ctrl+L**.

Use **2 GiB instead of the 1 GiB verified test target** if your host has enough free memory and you want to browse heavier websites:

```bash
PUPPY50_RAM_MIB=2048 bash launch_linux_v70.sh
```

To boot without any guest network adapter:

```bash
PUPPY50_NETWORK=off bash launch_linux_v70.sh
```

Use the "Network status" link on the homepage for the last **startup** test result. If the host switches networks after boot, the status page is not continuously refreshed; reboot for a fresh diagnosis.

## What "any network" can and cannot mean

QEMU user-mode networking routes permitted outbound connections through whatever network is available to the **host**. If the host switches from home Wi-Fi to Ethernet or phone hotspot, QEMU can normally reuse the active host connection when routes and firewall policies allow it.

**It does not mean** universal Internet access or the ability to bypass a network's security policy. It does not automatically join Wi-Fi SSIDs, perform WPA Enterprise authentication, get through a captive portal, make blocked sites work, or guarantee arbitrary VPN/firewall compatibility. For this virtual machine, connect or authenticate the host first. Physical Wi-Fi control requires a separate driver, firmware, network-manager UI and hardware testing track.

## Verification and limitations

The prior **v69** image visually displayed `https://example.com/` in Firefox at **1024 MiB** guest memory, with a separate verified CA-validated guest HTTPS connection. The v70 CI must verify RAM-root and CD eject, the clean homepage pixels, live guest DNS/DHCP and CA-validated public HTTPS. Other external websites are **shortcuts, not independently verified compatibility claims**. Network access may fail under some host policies.

The system is not tested as a physical bootable replacement for your older Intel i915 computer. It is not a production-maintained or security-certified OS. Browser updates, system package metadata, disk persistence and many device classes are not complete. Do not use it for sensitive accounts or transactions.
