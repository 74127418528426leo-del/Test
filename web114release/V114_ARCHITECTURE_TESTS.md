# Puppy50 v114: architecture experiments

These research images are separate from the published v114 ISO. All times below are from QEMU/KVM, not the physical Acer. Small samples cannot establish hardware-wide performance.

- **File layout:** a diagnostic monitor captured 8,235 startup file-open events and 1,444 eligible unique file entries. A six-boot matched comparison tested the unchanged v113 ISO, an unsorted root rebuild, and a trace-sorted rebuild, with two runs per image. The unsorted and sorted rebuilds averaged 15.80 and 15.69 seconds to Firefox's home frame; local JavaScript response averaged 19.13 and 19.25 seconds. The 0.11-second home difference was below the approximately 0.2-second polling sleep and the JavaScript result was slightly worse. Both filesystem trees and ISO checksums were verified; the sorted layout was not included in the release.
- **Firefox startup cache:** a 4,778,309-byte seed produced in an isolated VM was checked for internal application-only cache keys. A four-boot matched comparison showed 15.80 versus 15.79 seconds to the home frame. The seeded cache was not included in the release.
- **Earlier desktop:** a prototype averaged 16.20 versus 15.75 seconds to the home frame across four alternating runs per image. Its custom session and early graphics ordering are not proven safe on the physical Acer's Intel graphics or dual monitors, so it was not included in the release.
- **Firmware layer:** separating all firmware from the root produced a 406.42 MiB browser/system layer and a 257.87 MiB firmware layer; both together remained about 664.28 MiB compressed. Recombining them preserved the full root in bidirectional file and metadata checks. Firmware must remain available for future devices and both layers must be copied and verified before treating removal as compatible with the full image.
- **Copy scheduling:** in low-memory experiments, starting migration too early allowed the current memory check to pass before Firefox allocated its later memory. At 1.5 GiB, some configurations reached RAM-ready but later had very low available RAM and failed to load the expected post-ejection fixture page. Early copying was not included in the release; RAM-ready confirms the verified backing transition, not a promise of future browser headroom.

For a cold 30 MiB/s source, reading the current 664.28 MiB root takes at least about 22.14 seconds in aggregate, excluding boot and verification overhead. Initial boot reads may overlap startup and populate caches, so the later timed copy phase can be shorter; Firefox can appear while the rest is still being read. The eight-second browser and 384 MiB RAM-only Firefox goals remain unmet.
